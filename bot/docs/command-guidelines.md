# 机器人指令新增约束

本文是 EVE Sentry QQ 机器人新增或调整群聊指令时的强制约束。目标是让命令在 QQ
不同消息格式下行为一致，避免新指令被误判为分析名单、普通文本或其他业务命令。

## 1. 指令定义

- 每个功能必须有一个清晰的标准指令；别名只用于缩短输入，不改变语义。
- 指令使用中文短语，避免与已有指令前缀产生歧义。新增前先检查
  `分析`、`帮助`、预警订阅命令和查询命令集合。
- 需要目标的指令必须明确目标类型。例如：
  `查询人员 <名称>`、`查询军团 <名称>`、`查询联盟 <名称>`。
  预设的简写 `预设 监控 <名称>` 明确约定默认为人员，不根据名称猜测类型；其他类型必须显式指定。
- 标准指令、别名和目标字段必须集中维护，不能在多个业务模块中各自新增正则。

当前查询短命令集中在 `sentry_status.py` 的 `QUERY_ALIASES`：`查人`、`查军团`、
`查联盟`、`查星系`、`敌情`、`节点`、`查名单`；完整指令继续兼容。
`再查`/`刷新查询` 只复用当前群、当前用户 10 分钟内的文字查询条件，不缓存查询结果。
没有记录、记录过期或不合法时必须明确提示，不能默认为全量查询。

快捷预设的标准指令为 `预设 监控 [人员|军团|联盟|星系] 名称`、`预设列表`、
`删除预设 编号`；`预设` 展示列表和帮助。命令解析集中在 `query_presets.py`，
兼容 `预设，监控 名称`。只保存查询条件，点击才发起一次现有 OCR 查询，不创建周期监测。
名称长度 1–100 字且必须单行。按群隔离、每群最多 7 个、同类型同名称不重复添加；
所有群成员可使用，只有创建者可删除。创建者只存哈希，不额外保存明文 OpenID。
存储不设 TTL，但持久性依赖 Redis 配置，不能将“无 TTL”描述为保证永久保存。

## 2. 输入标准化

所有群聊指令必须先经过 `normalize_command_content()`，不得自行处理提及或斜杠。
标准化流程必须兼容以下输入形式：

```text
查询人员 Alice
/查询人员 Alice
@哨兵 查询人员 Alice
@哨兵/查询人员 Alice
<@!机器人OpenID> /查询人员 Alice
<@!机器人OpenID>/查询人员 Alice
```

提及 ID 不能假设只有字母数字和下划线；应按 QQ 提及的闭合格式识别。普通 `@名称`
格式需要在斜杠或空白处停止，不能把后面的命令一起吞掉。

## 3. 参数与错误处理

- 目标型指令缺少参数时必须返回明确提示，例如“请指定要查询的人员名称”，不能
  把空参数当成全量查询。
- 参数应去除首尾空白；保留名称内部空格；同一命令只产生一个明确的筛选字段。
- 解析失败必须回到统一的未知/格式错误处理，不得静默排队分析任务。
- 新增筛选字段时，同时更新服务端接口契约和本地响应格式；仅改变 QQ 文本时不要
  修改 HTTP/SSE wire 字段。
- 缺少参数的提示包含可照抄示例；记录最近查询时排除菜单、空参数、忙碌与提交失败，
  不得把其他用户或其他群的条件用于本次查询。复用条件仍经过原来的锁、校验和请求链路。

## 4. 消息分发顺序

`RiskBotClient.on_group_at_message_create()` 中的判断顺序必须保持：

1. 事件幂等去重。
2. 预警开启、关闭、状态命令。
3. 帮助命令。
4. 快捷预设管理命令。
5. 上线监测管理命令。
6. 查询命令（包括定向查询与再查）。
7. 裸 `分析` 命令。
8. 带名单的分析命令；其他文本不得误入分析队列。

新命令必须放入正确的分支，不得通过改变顺序抢占已有命令。

## 5. 指令面板

- `src/eve_risk/qq_panel.py` 的 `PANEL_ITEMS` 必须与可用标准指令同步。
- 面板按钮只负责把指令填入输入框，不能假设用户已经发送消息；带参数的指令应在
  描述中注明需要补充名称。
- 全局指令面板的 `预设` 替换重复的 `查询预警` 入口（不删除文字命令），保持十项。
  查询消息内的键盘与全局面板不同，只含三个固定查询与已保存目标的回调按钮，全部点击即执行。
  预设回调只携带编号，并按回调所属群重新读取和校验；已删除、跨群、损坏或缺失记录不得执行。
  不接受任意参数型回调来绕过预设校验，保留群查询锁与事件去重。
- 面板配置使用幂等同步命令：

  ```bash
  .venv/bin/eve-risk-configure-qq-panel
  ```

  同步前先确认服务器已部署包含新 `PANEL_ITEMS` 的版本。重复执行应返回
  `unchanged`，不得创建重复面板。

## 6. 测试要求

新增指令至少需要覆盖：

- 无提及、带空格提及、提及紧贴斜杠三种输入；
- `/命令` 和普通命令两种形式；
- 正常参数、缺少参数、带内部空格的参数；
- 机器人分发到正确业务分支，且不会调用错误的队列或回复路径；
- 指令面板内容包含标准指令。
- 预设的重复添加、容量上限（含并发）、所有权、群隔离、删除旧按钮失效、存储异常、
  点击重新查询、群忙碌和重复回调；保存不应发起 OCR 或入队分析。

提交前运行：

```bash
.venv/bin/python -m pytest -q
.venv/bin/ruff check src tests
```

## 7. 发布与边界

- 机器人改动统一在 `main` 开发并推送，由 CI 验证和部署。
- QQ 指令面板同步是独立的生产配置动作，代码部署不会自动意味着面板已更新；
  部署完成后必须单独复核面板状态。
- 涉及 HTTP、SSE、事件、游标、认证或 ESI wire 的变更必须同步对应服务端/契约
  文档，并按单体仓库的跨组件流程完成兼容性审查；生产部署和健康验证通过对应的
  GitHub Actions 及组件运维文档执行。
