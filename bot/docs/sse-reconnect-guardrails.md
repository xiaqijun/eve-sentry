# EVE Sentry SSE 重连约束

本文记录 2026-09-04 的 SSE 首字节阻塞与机器人永久等待问题，防止后续修改重新引入。

## 客户端行为

- SSE HTTP 读取必须有有限空闲超时，当前为 45 秒；服务端 heartbeat 为 15 秒。
- 除 HTTPX 的读取超时外，逐行读取也有独立 watchdog。连续没有任何字节时，
  `_stream_once()` 必须退出，让 `run_forever()` 执行退避重连。
- SSE 注释帧（例如 `: connected`、`: keepalive`）表示连接有数据活动，不能当作事件，
  但必须刷新底层读取超时。
- 事件游标只能在事件成功处理后写入 Redis；重连不得跳过未确认事件。

## 节点快照

`process_bootstrap()` 的初始节点快照有版本和 Redis 去重保护。不要把“连接重建”
简单改成每次都强制推送完整节点列表；只有首次初始化、版本变化或 Redis 状态丢失时才允许
触发完整快照。

## 服务端配合

服务端必须在返回 SSE 响应头后尽快发送至少一个字节，并保证 heartbeat 间隔小于客户端
空闲超时。客户端不能依赖服务端永远保持连接，也不能用永久阻塞替代对账机制。
