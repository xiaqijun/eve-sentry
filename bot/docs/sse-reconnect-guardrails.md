# EVE Sentry SSE 重连约束

本文记录 2026-09-04 的 SSE 首字节阻塞与机器人永久等待问题，防止后续修改重新引入。

## 客户端行为

- SSE HTTP 读取必须有有限空闲超时，当前为 45 秒；服务端 heartbeat 为 15 秒。
- 除 HTTPX 的读取超时外，逐行读取也有独立 watchdog。连续没有任何字节时，
  `_stream_once()` 必须退出，让 `run_forever()` 执行退避重连。
- SSE 注释帧（例如 `: connected`、`: keepalive`）表示连接有数据活动，不能当作事件，
  但必须刷新底层读取超时。
- 只有 `id: state:W` 而没有 `data` 的控制块只用于恢复原生 EventSource 游标；机器人解析器
  必须忽略它，不得生成空消息或覆盖尚未处理完成的事件。
- 事件游标只能在事件成功处理后写入 Redis；重连不得跳过未确认事件。
- 服务端当前 wire 事件包括 `bootstrap`、`alert`、`safe` 和 `monitoring_node`；其中
  `alert.data.event_type` 区分内部 `alert.entered` / `alert.updated`，`safe` 对应
  `alert.cleared`，机器人仍需兼容这些内部名称及目标 `node.updated` 映射。
- 机器人成功处理事件后把 `state:<seq>` 保存为 ACK；重连时同时发送该
  `Last-Event-ID` 和单调递增的 Redis 时间游标 `since`。前者保证乱序时间戳不会漏过持久事件，
  后者为没有持久序号的兼容事件提供时间回退，Bootstrap 负责权威状态对账；更旧的序号或
  后续非持久事件 ID 不得覆盖已确认的持久序号。持久序号不能沿用 7 天投递去重 TTL；否则
  安静运行后重连会失去可靠游标。
- `safe`（内部 `alert.cleared`）是服务端持久化的权威清空；服务端不得根据每个连接的前后
  快照临时合成持久清空。机器人若漏收 `safe`，可用权威 Bootstrap 的星系差集做一次幂等
  对账并发送补偿清空，不能把每次重连都当作新的清空事件。
- Bootstrap 已经把某星系校准为空后，随后到达的同一持久清空事件只做确认，不得再次推送
  清空消息；Redis 时间游标只能单调前进，迟到事件不得将它倒退。

## 节点快照

`process_bootstrap()` 的初始节点快照有版本和 Redis 去重保护。不要把“连接重建”
简单改成每次都强制推送完整节点列表；只有首次初始化、版本变化或 Redis 状态丢失时才允许
触发完整快照。

## 服务端配合

服务端必须在返回 SSE 响应头后尽快发送至少一个字节，并保证 heartbeat 间隔小于客户端
空闲超时。服务端以数据库一致快照水位 `W` 为边界，先完整重放 `seq <= W` 的持久状态事件，
再发送 `state:W` Bootstrap；快照未就绪、落后于事件或落后于客户端游标时不得用空状态或
旧状态替代。客户端不能依赖服务端永远保持连接，也不能用永久阻塞替代对账机制。
