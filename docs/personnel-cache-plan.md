# 全量人员档案与分级刷新方案

状态：2026-09-10，M1～M3 及 M4 的本地实现已接入并验证，默认关闭；尚未发布/启用生产。
本文是业务人员缓存的唯一设计入口。当前生效的配置仍以
[服务端部署](server-deployment.md)和 [Gateway 缓存](../esi-gateway/docs/cache-and-storage.md)为准。

## 1. 目标与边界

优先顺序：来敌/清空及时性 → 人员识别 → 当前资料新鲜度 → 全量历史覆盖。
全量指所有实际出现、且经 ESI 确认身份的角色，不扫描 EVE 全部角色。
缓存过期表示需要刷新，不表示删除人员身份。角色 ID 是主键；军团/联盟按 ID 比较，
名称只负责展示。没有联盟必须表示为无联盟，不能把两个空 ID 当成同联盟。

不恢复 zKill 战绩、威胁评分或等级请求；zKill 链接、头像地址由角色 ID 生成。
机器人手动战报分析独立保留。不改变 Presence、OCR 原始上报、事件历史的职责。
档案中不保存“此人当前仍在某星系”作为实时事实，也不永久缓存敌我分类结论。

## 2. 数据模型

生产使用 PostgreSQL 长期档案和有界进程内热点副本，无需新增 Redis。
Gateway 现有可选 PostgreSQL/Redis 请求缓存继续使用，不充当业务活动状态源。

| 表 | 主键/索引 | 数据与规则 |
| --- | --- | --- |
| personnel_profiles | character_id；last_seen_at | 标准姓名、姓名确认时间、组织归属、归属实际获取时间、首次/最近出现、资料版本 |
| personnel_names | name_key | 已确认规范化姓名→角色 ID；active=0 保留失效旧名；冲突不自动覆盖 |
| personnel_organizations | kind + entity_id | 军团/联盟名称及获取时间；长期保存，不固定每 7 天补查 |
| personnel_refresh_jobs | kind + entity_key + context_key；next_due_at | 优先级、下次执行、失败次数、任务版本、租约及本次租约领取版本 |
| personnel_backfill_progress | source | 旧缓存/历史回填游标、导入数及拒绝数，可断点恢复 |

时间使用 UTC 时间戳；姓名索引仅 trim + casefold，不做去标点、压缩内部空格或模糊纠错。
上报原文和历史姓名不改写。明确改名后原子更新当前姓名及新索引，停用原有效索引；
同名映射冲突必须退出事务；实时解析任务保留重试，回填冲突计入 rejected 供管理员核查，不能把其他角色历史迁移过来。

身份和组织归属分别记录获取时间，资料共用修订号：归属结果不能覆盖姓名；组织名称回填也不能把
归属变更误认为刚验证了姓名。旧结果不能覆盖新结果；相同数据同一时间的冲突不得任意胜出。
所有写入必须拒绝无效/非正 ID、非有限时间戳和错误的组织类别。

联系人声望不存入公共档案。继续按授权主体及 contacts 快照版本缓存，只在服务端使用；
后台检查发现授权切换/撤销时先隔离旧快照，再加载新上下文（检查约每 5 个调度周期）。
热读不请求私有 ESI，失败可使用最长 1 小时的同上下文成功快照。军团/联盟名称缺失不阻塞分类。

## 3. 读路径

1. OCR 入站先批量读内存姓名索引，未命中再批量读数据库，数据库读有界，不持全局状态锁。
2. 可信姓名映射命中立即返回角色 ID；资料过期仍可读，后台提升刷新优先级。
3. 完全未知姓名先返回 pending，进入实时队列；视觉来敌和人数不等待 ESI。
4. 姓名解析成功先存身份，再批量刷新归属；组织名称缺失由独立任务补齐。
5. 仅可信成功值长期保存；明确 not_found 短期负缓存。超时/限流/5xx/认证错误不算 not_found。

冷启动只预热当前/近期人员，不把全部档案加载到内存。内存淘汰不删除数据库。
首次识别仍受 ESI 延迟影响；缓存命中后身份读取与组装 P95 <50ms 是待压测目标，
不包含 OCR、网络和 QQ 投递，不作为已经达到的生产指标。

## 4. 字段与人员两维分级

| 级别 | 人员范围 | 归属刷新初始目标 |
| --- | --- | --- |
| P0 | 当前未知身份/映射冲突 | 立即排队 |
| P1 | 当前有效观察中的人员 | 5 分钟 |
| P2 | 离开后 24 小时内出现过 | 1 小时 |
| P3 | 最近 1～7 天出现过 | 6 小时 |
| P4 | 最近 7～30 天出现过 | 7 天 |
| P5 | 超过 30 天未出现 | 30 天 |

这些是正常负载下的目标，不是上游限流时仍保证完成的硬 SLA。姓名初始 90 天校验一次，
命中不等待校验；资料查询顺带发现改名立即更新。组织名称按 ID 长期复用，新 ID 才补查，
顺带发现改名更新即可。联系人快照初始沿用约 5 分钟，按授权主体而非逐人刷新。
本地黑白名单/规则修改立即提升受影响当前人员的重算任务。

过期身份先用；但过旧的友军归属/声望不能作为屏蔽当前来敌信号的唯一证据。
建议当前分类所用归属的软期限为 5 分钟、最大信任年龄初始 1 小时；超限且无其他有效证据时
保留身份展示、分类标为待确认，不根据截图共享图标把每个人都判为敌对。
这个“最大信任年龄”独立于档案保留期，已实现并测试，不沿用无限旧组织友军豁免。

## 5. 调度与资源预算

实时识别与巡检分别保留执行容量，不能仅用一个有优先级的单线程队列。
当前实现：实时 2 个执行槽、后台初始 1 个，后台可增加到 4 个；公共请求共享每秒最多约 5 次的
启动节流及上游退避。槽位/批量上限当前为代码默认值，不是环境变量。依据 CPU 负载、每条数据库
处理耗时、ESI 批次耗时、实时到期积压和退避状态增减，不能仅以 CPU 空闲判断。

- 实时积压或上游退避时，后台停止领取新任务；已在途请求有总超时，不能无限占槽。
- 空闲时提前最多半个刷新周期处理到期任务；仍有资源时按资料年龄遍历冷人员。
- 有限批量领取，不把全量档案灌入内存；当前解析/姓名/归属每批最多 100 个实体，上游归属接口上限 1000。
- 不为凑满批次等待实时请求；后台预取分页和内存缓存均有硬上限。
- 同类实体任务只保留一份；再次出现可提升优先级，不能因已有 P5 任务而拒绝 P1。
- 领取使用数据库租约和 SKIP LOCKED；租约到期允许重试，旧租约不能提交资料结果。
- 领取时记录任务版本；任务在执行中被重新请求时，完成旧版本不能消掉新的刷新意图。
- 失败保留成功资料，指数退避并加抖动，尊重 Retry-After；错误日志不能记录令牌或敏感响应。
- 低优先级保留少量领取份额；以最老逾期年龄告警，不能让冷人员无限饿死。

明确未找到负缓存 60 秒，当前不自动延长；请求失败不增加身份否定证据。
全量刷新吞吐量应按唯一人员/组织量、批量大小和可用请求预算估算，不按客户端数估算。

## 6. Gateway 协同与新鲜度

服务端负责“谁活跃/谁先刷新”；Gateway 负责公共请求缓存、合并及上游限流。
`/characters/affiliation/` 返回 character_id、corporation_id、可选 alliance_id/faction_id，
不返回组织名称。分类只需要 ID；遇到新组织 ID 才额外查名称。

Gateway envelope 已兼容新增逐实体 freshness 元数据：fetched_at、expires_at、stale、last_validated_at，
老消费者忽略新增字段；遇到旧 Gateway 不得捏造“刚从 ESI 获取”的时间。
当前不新增客户端强制刷新参数，不绕过共享限流或上游有效缓存期。
只有真实成功加载/条件验证才更新验证时间，读取旧值不重置其年龄。服务端 5 分钟调度目标
与 Gateway 默认 300 秒归属 TTL 对齐；已有显式 3600 秒配置需在部署时更新。
上游 420/429 经 Gateway 映射为 429，并透传经过校验的 Retry-After；服务端不在限流时绕过网关直连。

## 7. 刷新后的分类与推送

刷新成功先更新档案；只有存在有效当前观察才尝试重新分类。
结果应用校验角色资料修订、有效活动项/上报关联、观察起止时间与星系、规则对象和联系人快照。
活动项已失效则退出；观察或资料已更新则重新排队，不用历史波次累计名单恢复当前人员。
不允许旧任务把已经清空、离线、移动或重新开启后的状态覆盖回去。

| 变化 | 行为 |
| --- | --- |
| pending→确认敌对、友军→敌对 | 更新当前名单，补发人员预警，不重复新建同一视觉来敌波次 |
| 敌对→友军 | 更新当前名单，推送人员更正，包括名单变为空的情况 |
| 姓名变化但角色 ID 相同 | 更新资料和显示，不单独推送，不当新人 |
| 组织归属变化但分类不变 | 更新资料，不重复预警 |
| 数据未变 | 只更新校验时间，不产生人员预警 |
| 人员已离开/星系已清空 | 只更新档案，不推送当前预警 |

人员从敌对名单移除不等于星系清空；视觉人数与已确认名单分别维护。
当前人员名单必须允许移除/更正；波次历史仍可保留“曾被判为敌对”的原始证据和更正记录。
不能直接复用 `hostile_waves.personnel_json` 的累计 union 作为刷新后的当前权威名单。
事务内保存当前分类/名单变更与持久事件，事务提交后唤醒 SSE，机器人按状态版本及角色 ID
集合去重。同角色改名不改变人员指纹；最后一名敌对被更正时不能因为空名单就跳过发送。
支持无变化恢复和重连重放，不因刷新任务重试生成重复 QQ 消息。

## 8. 自审记录与接入门槛

| 风险 | 当前代码证据 | 设计修正/验收 |
| --- | --- | --- |
| 一次慢 ESI 阻塞全部刷新 | EsiWorker 单线程 | 独立实时/后台容量、在途超时和限流预算 |
| 刷新先删除，失败后失去身份 | _invalidate_ocr_character_profile_cache | 成功后替换、失败保留、版本比较 |
| 旧响应被标新鲜 | RemoteEsiClient 只返回 data，时间未透传 | Gateway 逐实体时间，旧网关明确退化 |
| 历史累计名单无法移除友军 | hostile_waves personnel_json 合并 | 当前名单与历史名单分开，更正事件事务化 |
| 改名触发重复推送/空名单不更正 | bot 原姓名指纹、跳过空名单 | ID 指纹，已有 alert.updated 承载更正，消费者将人员移除标为“人员名单更正” |
| 全量任务重启/多实例重复 | 内存 pending 队列 | 持久任务、版本租约、过期恢复、幂等结果 |
| 缓存军团名覆盖归属 | 资料混合更新 | 字段获取时间独立，名称回填按当前组织 ID |

结论：上述接入门槛已落实在本地实现及回归测试中；生产启用仍需要灰度和真实端到端验收。

## 9. 分阶段开发与回滚

| 阶段 | 交付 | 状态 |
| --- | --- | --- |
| M1 | PostgreSQL 档案/姓名/组织仓储，持久租约任务，分级/自适应策略 | 已实现，真实 PostgreSQL 测试通过 |
| M2 | 解析器接入、批量合并、断点回填、Gateway freshness、独立调度 | 已实现，本地启动和 shadow/on 验证 |
| M3 | 资料/规则/contacts 重分类、当前名单更正、原子事件、机器人 ID 去重 | 已实现，空名单及清空防复活回归通过 |
| M4 | 管理观测 API/UI、10 万冷任务积压测试、灰度开关 | 本地实现已完成；生产发布、运行观察和端到端验收尚未执行 |

默认 `EVE_SENTRY_PERSONNEL_CACHE=off` 不迁移、不启动档案线程，不要求客户端升级。
主要入口：`app/esi/personnel_setup.py`、`personnel_runtime.py`、`personnel_archive.py`、
`personnel_schema.sql`、`personnel_policy.py` 和 `personnel_backfill.py`。
仓储接收带事务管理及字典行工厂的 PostgreSQL 连接工厂，迁移必须显式调用；SQLite 适配仅供
确定性测试，不是新增生产后端。`tests/test_personnel_archive.py` 验证数据与调度契约，
`tests/test_personnel_postgres.py` 验证真实行锁、租约隔离及结果/任务完成的事务一致性，
加上 `tests/test_personnel_live_store.py` 已进入发布前 PostgreSQL 门禁；未配置测试 DSN 时跳过，
不能视作已通过。本次在单独启动的本地 PostgreSQL 16 临时实例及随机 schema 中执行了真实测试。

调度器按实体合并重复请求；普通巡检仅提级，不取消已安排的成功刷新时间或失败退避。
租约为 90 秒，默认网络超时 10 秒，超时/过期结果不能提交。内存热点、待解析及负缓存各限制为
20000 条，数据库读取每批 500 条，回填/巡检每页 100 条。冷历史缺失归属也保留 P5，不挤入实时队列。

灰度采用独立服务实例开关：`off → shadow → on`。shadow 建档和观测但保留原读取，人工比对
已有 Gateway 指标及档案状态后启用；当前没有逐节点开关或自动影子差异判定，避免混合状态源。
迁移仅导入 ESI 确认过的 name/ID；数据冲突进入人工/后台验证，不能凭 OCR 猜测回填。
回填按游标分页、可断点恢复，真实 observed_at 用于活跃度，不以迁移时间把所有人升级为 P1。
运行期数据库失败保留已成功内存资料并重试，不自动切换回可能产生不同分类的旧解析器；健康项显示 degraded。
回滚停止新调度并恢复旧读取，不删除新增表或历史资料。生产仅经受保护 GitHub 工作流。

## 10. 验收矩阵

- 档案跨连接/重启读取；冷热淘汰不丢身份；军团/联盟名称共用缓存。
- 改名旧索引停用、新名合并已有 ID；冲突拒绝；过期旧结果不能覆盖新归属。
- 无联盟是正常结果，不是查询失败；缺失整条角色结果不得清空该角色归属。
- 并发领取不重叠；租约失效不能提交；在途提级不丢请求；失败退避保留旧数据。
- 名单 100/1000 人、后台 10 万档案积压下实时队列等待有界；批次不会无限扩大。
- 新鲜身份命中无需 ESI；反复 OCR 按名字/角色去重；共享组织名称不重复请求。
- ESI/Gateway/数据库不可用、429、部分成功、旧数据降级、重启恢复均有测试。
- 改名不发消息，敌我变化发更正，空名单更正可投递；清空后迟到刷新不复活。
- 全量服务端、真实 PostgreSQL、Gateway、机器人、客户端契约和前端回归通过后才进入 M4。

当前新增指标：内存/数据库命中、唯一人员数、按任务类型和级别的积压/最早到期时间、最近批次
耗时、后台槽位、刷新成功/失败、存储异常、队列拒绝和租约迟到结果。由管理员 Gateway 页展示，
详细字段见 API 参考。上游请求和 QQ 投递延迟沿用原观测；真实端到端 P95 仍需生产灰度测量。
任务日志使用关联 ID，不记录密钥；人员数据按项目已有访问控制提供，不新增公开枚举接口。
