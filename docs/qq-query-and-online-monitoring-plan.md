# QQ 查询与上线监测实施方案

本文冻结 QQ 机器人查询菜单、按需 OCR 和上线监测的产品语义。实现不得把实时
Presence、历史预警数据和一次性 OCR 名单混为一套状态。

## 1. 查询菜单

`@机器人 查询` 只打开 Markdown 查询菜单，不直接发起 OCR。菜单使用 QQ 静态按钮模板，
按钮均采用 `action.type=2` 指令模式：

| 按钮 | 指令数据 | 自动发送 |
| --- | --- | --- |
| 查询指定星系 | `查询星系 ` | 否 |
| 查询节点敌情 | `查询节点敌情` | 是 |
| 查询指定人员 | `查询人员 ` | 否 |
| 查询指定军团 | `查询军团 ` | 否 |
| 查询所有节点 | `查询所有节点` | 是 |
| 查询指定联盟 | `查询联盟 ` | 否 |
| 查询预警节点 | `查询预警节点` | 是 |
| 上线监测 | `上线监测 ` | 否 |

按钮模板 ID 通过 `QQ_QUERY_KEYBOARD_ID` 配置。模板未配置或 QQ 拒绝按钮时，机器人必须
退化为普通 Markdown 指令菜单，现有文字指令继续可用。

## 2. 数据语义

| 功能 | 是否触发 OCR | 权威数据 |
| --- | --- | --- |
| 查询指定星系 | 是，只查询该星系的在线窗口 | 本次 `query_id` 的原始名单 |
| 查询节点敌情 | 否 | 服务端当前活动预警数据 |
| 查询指定人员 | 是，查询全部在线窗口 | 本次 OCR 名单及服务端识别结果 |
| 查询指定军团 | 是，查询全部在线窗口 | 本次 OCR 与 affiliation 结果 |
| 查询所有节点 | 是，查询全部在线窗口 | 各窗口本次完整 OCR 名单 |
| 查询指定联盟 | 是，查询全部在线窗口 | 本次 OCR 与 affiliation 结果 |
| 查询预警节点 | 否 | heartbeat 与 `monitoring_nodes` 状态 |
| 上线监测 | 按调度需要 | 最新成功的完整 OCR 名单 |

### 2.1 查询指定星系

指令为 `查询星系 S-KSWL`。服务端只向当前 heartbeat 中 `system_name=S-KSWL` 的在线窗口
下发命令。结果只返回去重后的人员名称和响应节点数，不返回敌我、军团、联盟、声望、
星系资料或 zKill。历史活动名单不得补入本次结果。

### 2.2 查询节点敌情

指令为 `查询节点敌情`。直接读取 `/api/v1/bootstrap` 中的当前活动预警数据，按星系输出
敌对人数和已识别人员，不创建 `query_id`，也不唤醒客户端 OCR。

### 2.3 查询人员、军团和联盟

指令分别为 `查询人员 <名称>`、`查询军团 <名称>` 和 `查询联盟 <名称>`。服务端向全部
在线监控窗口下发一次 OCR，机器人只筛选本次返回的名单。军团和联盟使用角色 affiliation
结果判断，不允许用历史预警名单补齐。

### 2.4 查询所有节点

指令为 `查询所有节点`。向全部在线监控窗口下发一次 OCR，按节点和星系返回本次完整
人员名单，包括没有被判断为敌对的名称。空数组表示窗口本次确实没有识别到人员。

### 2.5 查询预警节点

指令为 `查询预警节点`。读取 heartbeat 和 `monitoring_nodes`，用 Markdown 表格返回节点、
状态、星系、当前敌对人数和最后心跳，不触发 OCR。该功能用于查看基础设施健康，不能用
它替代“查询节点敌情”。

## 3. 异步查询响应

主动 OCR 查询必须拆分为创建和等待两个阶段：

```text
用户指令
  -> POST /api/v1/ocr/query
  -> 立即回复 query_id、目标节点数和“任务已下发”
  -> 后台轮询 GET /api/v1/ocr/query/{query_id}
  -> 全部返回或达到软超时
  -> 主动发送 Markdown 结果
```

同一群同时只允许一个主动 OCR 查询。Redis 锁和 `query_id` 投递标记防止按钮连点、事件
重放或后台任务重复发送。查询菜单、节点敌情和预警节点不占用 OCR 查询锁。

## 4. 上线监测

“上线”定义为目标出现在监控客户端当前人员名单中，不表示 EVE 账号登录状态。支持：

```text
上线监测 人员 Alice 30s
上线监测 军团 Rat Nation 1m
上线监测 联盟 Example Alliance 5m
上线监测列表
取消上线监测 M001
取消上线监测 人员 Alice
取消上线监测 军团 Rat Nation
取消上线监测 联盟 Example Alliance
取消全部上线监测
```

- 最低间隔为 30 秒，默认 60 秒；
- 监测任务持久化到 PostgreSQL；
- 到期规则合并执行，30 秒内最多创建一次全节点 OCR；
- 机器人进程保留最近一次完整监测 OCR 结果，默认 30 秒内优先复用，不重复唤醒客户端；
- `未出现 -> 出现` 只通知一次；
- 连续两次成功完整 OCR 未发现后重新布防；
- 节点离线、OCR 失败或部分节点未返回不能作为目标消失依据；
- 删除后立即停止调度并清理 Redis 运行态；
- 单条删除支持任务编号或“类型 + 名称”，批量删除使用独立明确指令。

## 5. 时延与负载目标

- 查询菜单、节点敌情和预警节点：正常情况下 1 秒内返回；
- 指定星系 OCR：通常 5 至 10 秒；
- 全节点 OCR：通常 7 至 15 秒；
- 15 秒为软超时，返回已有结果并标出未响应节点；
- 一个调度周期内的多个群和多个监测规则必须复用同一份全节点 OCR 结果；
- 查询 OCR 不能修改 Presence、波次、地图红色状态或正常预警清空逻辑。

## 6. 实施与验收

1. 机器人支持静态查询按钮模板和无模板降级；
2. 服务端 `/api/v1/ocr/query` 支持可选 `system_name` 精确选择目标窗口；
3. 查询客户端拆分创建、等待和结果格式化；
4. PostgreSQL 增加上线监测任务表，机器人启动监测调度器；
5. 覆盖按钮 payload、命令解析、星系目标筛选、无 OCR 快速查询、查询锁、监测间隔、
   状态去重和删除操作测试；
6. 推送 `main` 后分别通过服务端和机器人 CI/CD 部署并验证。
