# 星图监控范围

本功能为本地开发版本，尚未提交、部署或发布客户端。

## 配置与使用

管理员在 Web「星图态势 → 监控范围」选择监控星域、额外包含星系和排除星系。
最终范围为 **所选星域全部星系 ∪ 额外包含星系 − 排除星系**，排除优先。
名称和 ID 来自本地 SDE，不依赖实时 ESI；保存前显示数量，空范围、未知 ID、过期版本不能保存。

旧配置默认不启用限制，升级不会突然停止现有监控。开启「启用区域限制」并保存后服务端立即生效，
客户端经心跳响应及 SSE Bootstrap 同步，无需重启。关闭限制恢复原上报行为，地图仍展示选择的拓扑。

- 范围内：图标检测、OCR、上报和远端预警正常运行。
- 范围外或位置未知：保留本地检测、OCR 和本地预警，不发送常规敌情或名单；认证与诊断心跳继续，
  不将“仅本地预警”误报成网络断线。
- 多窗口分别判断；全部本地监控窗口在范围外时不接收其他星系的远端告警。
  没有本地监控窗口的独立只读预警端仍接收服务端范围内预警。
- 清理待发/离线队列中的区域外数据；在途请求由服务端再次检查。进入范围后上报当前画面，不重放旧敌情。
- 区域外本地计数不受服务端统一状态模式屏蔽、不被 Bootstrap 清零。
  本地声音仍遵守原预警开关、静音和音量设置，配置不会擅自打开预警。

## 一致性与兼容

服务端决定范围，客户端不能覆盖。区域外 Presence/OCR 返回 HTTP 200 和
`accepted:false, ignored:true, local_only:true, reason:outside_monitoring_scope`，不触发离线重试。
离开范围的 Presence 仍执行来源迁移，立即撤下旧星系的该节点。诊断心跳保留，
区域外窗口的公开投影为 `monitoring=false, local_only=true`，不计为远端监控节点。

活动星图、Bootstrap、集成查询和 SSE 过滤区域外数据，被过滤的 SSE 仍推进游标。
旧观察通过维护任务失效；快速移除/重加前先完成旧范围清理，避免恢复旧敌情。
历史上报和事件不删除，移除覆盖不能解释成视觉确认清空。

仅更新服务端可过滤旧客户端上报，但不能保证旧客户端本地预警和队列切换。
完整功能必须发布新客户端；服务健康不等于完成真实画面、声音和 QQ 端到端验收。

## 存储与运维

`GET/PUT /api/v1/admin/map-settings` 沿用管理员认证及会话 CSRF 校验，
仅接收开关、配置版本和三组 ID，不接收任意路径或远程地址。并发保存校验 `version`。
SDE 或目录不可用时显示错误，保留原配置。

保存到地图配置旁的 `.monitoring.json` 文件，例如 `intel_map.monitoring.json`；同目录临时文件、
fsync、原子替换。部署归档不覆盖此 sidecar。启动时它优先于环境中的地图 source/region/system 默认值，
SDE 路径仍可由环境更新。须备份文件并保证服务用户权限；损坏时启动报错，不静默恢复全范围。
保存过新配置后，旧 `/api/map/config` 写入和 `/api/map/refresh` 返回 409，避免绕过统一配置入口。

业务回滚可关闭范围限制；回滚到不认识 sidecar 的旧服务端会忽略限制，须提前确认。
范围限制不替代用户权限隔离。服务端部署与客户端发布仍须使用受保护的 GitHub 工作流。

## 验收

检查范围组合/排除、空范围、未知 ID、并发冲突、写盘失败；双窗口跨范围、来敌/清空和声音；
旧客户端、断线恢复、离线队列、快速切换；星图/远端/QQ 一致性；重启和再次部署后配置保留。
