# EVE Sentry 与 GloryNavy_Seat 接入

状态：2026-10-25。当前收费合同只按服务端确认的认证客户端有效在线时长计费；监控奖励只按每个星系主节点的确认在线时长发放。事件次数、事件投递、客户端 ACK、预付授权、释放和退款不参与收费，也不保留兼容接口或历史账表。

## 当前数据流

- Sentry 保存密钥状态、主节点监控贡献区间和客户端认证心跳在线区间。客户端通过心跳 `details.alert_scope` 明确上报所勾选账号所在的中心星系；服务端按配置地图解析，每个选中的规范星系产生一条 `client-usage`。同账号其他机器的监控贡献、地图邻居和未选账号都不能扩大收费范围。
- Seat 保存账号归属、星系归因、按小时的预警价格与监控奖励价格，并在 exchange 内完成果壳币入账/扣款。
- 每个星系单独计量；同一星系只有主节点产生监控奖励。预警选择 N 个星系时，在线时长费用按 N 个星系分别计算。
  监控贡献和在线区间的幂等身份均包含 `account_id + key_id + client_id`，避免本地运行时 ID 重用
  把不同账号的计费事实合并。
- 相邻有效心跳形成一个在线区间，重复提交按客户端和时间边界幂等；认证归属、连接、选择 revision 或规范星系集合变化会切断区间。选择 A→B→A 也更换 revision，不对跨切换区间猜测补扣。

## Sentry 接口

服务端接口使用 Seat 集成 Bearer Token：

- `GET/PUT /api/v1/integrations/seat/alert-consumption`：读取或同步收费开关。
- `GET /api/v1/integrations/seat/monitor-contributions`：分页导出主节点监控贡献。
- `GET /api/v1/integrations/seat/client-usage`：分页导出认证客户端在线区间；同一时段明确选择多个中心星系时，每个 `system_id` 返回一条记录，`usage_id` 以星系归因为幂等边界。

事件、投递、ACK、alert-grants 及其对账接口已删除。接口不接收价格和币额，Sentry 不写 Seat 币账。

## Seat 结算约束

Seat 以 UTC 区间秒数和当前生效的小时价格计算果壳币，按账号和 `system_id` 独立幂等入账。价格修改只影响新的结算区间；前端只展示余额、预警价格、监控奖励价格和累计花费/奖励。

## 发布检查

2026-10-25 范围修复：先部署服务端，再更新客户端到 1.0.78 或以上。旧客户端不带范围、空选择、未知星系或矛盾的名称/ID 不产生新消费证据，不再按账号全部监控星系回退，也不事后补扣。已有证据、幂等键和账目保持原样。收费关闭期间先验证单选 R-YWID 只生成一份用量，确认客户端选择与服务端证据一致后才恢复收费；SeAT 继续使用暂停窗口保护，避免补扣暂停期。

2026-10-24 修复：PostgreSQL 启动迁移按实际列定义识别并替换旧消费唯一索引，
同时移除监控贡献表中被 PostgreSQL 截断名称的旧身份约束。新身份包含账号、密钥、
客户端、星系和区间，已有证据不改写；重复启动保留正确索引，不重复重建。
迁移与启动事务一起提交，重复数据或非预期索引定义会使迁移失败并回滚，不删除记录来继续启动。
星系归因使用命名列读取，兼容生产 PostgreSQL 的字典结果。

上线前先发布 SeAT 的后续区间累计取整修复，再恢复 Sentry 证据写入。验收须同时看到
新的认证客户端在线区间、非空星系归因、SeAT 游标推进和新增扣费账目；接口返回 200
不足以证明计费正常。无可靠历史消费证据的停计费时段不推算补扣，既有余额和历史币账不重算。
