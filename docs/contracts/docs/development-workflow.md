# EVE Sentry 多仓库开发流程

本文档是 EVE Sentry 多仓库协作方式的唯一权威来源。Codex 会话 ID、工作树路径
和本机置顶状态不写入仓库；长期稳定的角色编号、仓库职责和交付门禁记录在这里。

## 角色与仓库

| 角色 | 职责 | 主要仓库 |
| --- | --- | --- |
| `00` 总控、架构与集成 | 接收需求、拆分任务、指定写入者、汇总结论和跨仓库验收 | 只协调，不固定拥有实现仓库 |
| `20` 服务端与跨仓库协议 | HTTP、SSE、OpenAPI、JSON Schema、DTO、示例和兼容性测试 | `eve-sentry` |
| `10` 预警客户端 | 桌面 UI、OCR/截图、客户端状态、更新和服务端连接 | `eve-sentry-client` |
| `20` 预警服务端 | HTTP/SSE、认证、PostgreSQL、Web 控制台和服务端业务 | `eve-sentry` |
| `30` ESI Gateway | 公共 ESI 代理、鉴权、缓存、限流、健康检查和指标 | `eve-sentry-esi-gateway` |
| `40` 机器人 | 事件消费、消息平台交互、去重、游标恢复和机器人通知 | `eve-sentry-bot` |
| `90` CI/CD 与生产发布 | 工作流、部署、健康验证、回滚和跨仓库上线验收 | 按发布范围只读或修改相关仓库 |
| `99` 工具链维护 | Codex、GitNexus、索引和开发工具故障 | 不承担产品功能开发 |

## 工作流

1. 新需求先由 `00` 确认范围、受影响仓库、依赖顺序和验收条件。
2. 每个受影响仓库只能有一个写入任务；其他任务可以只读审阅，但不得并行修改同一仓库。
3. HTTP、SSE、事件字段、游标、鉴权或 ESI 线协议发生变化时，先由 `05` 更新或确认契约与兼容策略。
4. 各组件任务只修改自己拥有的仓库，并在本仓库内完成影响分析、测试、提交和推送。
5. 跨仓库联调由 `00` 汇总；契约兼容性由 `05` 复核，不能用复制实现代码代替契约。
6. 只有 `90` 负责生产部署、发布顺序、健康检查和回滚。组件任务不得自行触发生产部署。
7. 上线完成后由 `00` 记录结果、剩余风险和后续任务，并关闭或归档临时任务。

## 边界规则

- 五个仓库独立版本、独立提交和独立发布；一个提交不得跨越多个仓库。
- `eve-sentry/docs/contracts` 保存可发布的线协议、示例和兼容性测试；协议定义不依赖应用实现。
- 服务端不重新吸收客户端、Gateway 或机器人实现；共享行为通过契约和发布包协作。
- Gateway 不拥有 EVE SSO、用户令牌或应用解析器；这些仍属于服务端。
- 机器人和客户端必须持久化并恢复服务端定义的事件游标，不自行重新定义 SSE 语义。
- 跨仓库变更默认保持向后兼容。删除字段、改变类型或改变游标语义必须按契约版本策略处理。
- 审阅任务默认只读；只有总控明确指定的实现任务可以写入目标仓库。

## 完成门禁

组件任务交付前必须满足：

- 变更范围符合仓库职责，没有夹带其他仓库实现。
- 相关单元测试、集成测试和静态检查通过。
- 线协议变化已更新契约、示例和兼容性测试。
- 提交采用 Conventional Commits，工作树中用户原有修改得到保留。
- 需要上线时，提交已推送并交由 `90` 检查 CI、部署和回滚条件。

`00` 只有在所有受影响组件和契约检查均完成后，才能宣布跨仓库任务完成。
