# 星系当前状态与单主监控

本页说明本轮实现；生产是否已切换以受保护工作流及运行验收为准。
它补充[人员缓存方案](personnel-cache-plan.md)，不替代[API 参考](api-reference.md)。

## 采集与来源选择

每个窗口每次启动生成新的 `capture.session_id/session_epoch`，成功截图递增 `sequence`。
Presence 先上传人数和该帧指纹，OCR 后上传同一帧指纹及质量信息；截图、坐标不上传。
持续成功采集即使画面不变也续期；画面相同允许较早 OCR 结果复用，画面改变或会话切换则丢弃旧结果。
`session_epoch` 为客户端纳秒时间整数，第三方实现必须无损传输整数；系统时间回拨可能导致会话被拒绝，
应先恢复正确时间，不能绕过旧会话校验。来源排序使用服务端入队序号，不使用该时钟。

- 每个星系选择最先有效进入、连续驻留最久的窗口。有效零人数仍保持驻留；停止、离开、失效后重新排队。
- 备用窗口保留候选原始数据，不与主窗口合并。主窗口健康时，备用上传更快不会抢占。
- 最近 5 个独立采集序号中 3 次 OCR 边界明确截断，有合格备用时提升最早的合格备用；旧主及更早的不合格备用排到后面。
- 合格备用须有 45 秒内成功采集，且当前为零，或最新名单质量完整、指纹与当前采集一致。重复上传同一帧不增加质量证据。
- 质量 `complete` 仅表示 OCR 框未碰到截图边界，不保证姓名识别正确；无框或旧客户端没有证据时为 `unknown`。
- 旧客户端仍可参与基本顺序选择，但不能提供可靠截断接管证据；同窗口建立新格式会话后拒绝无会话信息的旧上报。
- 采集租约暂定 45 秒，覆盖客户端最大扫描间隔及网络余量；它不是视觉清空等待时间。视觉零人数沿用客户端连续两帧确认。

## 同一份当前结果

PostgreSQL 新增共享表 `system_current_state`，每个规范化星系键一行。
为兼容原有 `entity_key` 和未知星系输入，物理主键是规范化星系名 `system_key`，官方 `system_id` 保留在状态载荷中；
没有为每个星系单独建表。客户端会话、采集序号、候选质量记录留在原始 `active_intel` 元数据中。

`state_version` 使用已提交 `intel_events.seq`。原始更新、状态事件、当前状态同一事务提交，
数据库事务锁保证事件序号提交顺序；相同语义结果不产生新事件。状态表由已有最新事件增量回填，不删除上报或历史。
Bootstrap 和星图/SSE 快照在同一数据库快照中读取当前结果与事件水位，返回 v1 兼容的合成 `active_intel`；
原始 `/active-intel` 和历史接口继续提供上报明细，不应再用于自行合并自动监控敌情。

监控有效零人数、主来源切换、名单分类变化、失联、恢复均更新同一结果。
失联/停止/离开没有备用时发布 `freshness=unknown`，保留上次人数/名单，不发送假清空；
即使上次数量为零，也显示采集未知。有效备用零人数或新的有效主帧才确认清空/恢复。
手动/频道情报继续按原规则独立存活、合入当前结果；监控零人数不能清除它们。
QQ 按需 OCR 使用独立查询身份空间，不移动监控来源、不污染自动名单。

后台维护约每秒检查过期与接管，不依赖页面读取触发。持久化失败会返回错误并标记修复，
维护任务按数据库写入队列顺序重试内存快照及事件；修复失败不冒充成功，原始数据库事务保持回滚。
进程在失败后退出时，依赖客户端重试及重启对账，不能将尚未提交的内存状态称为已持久化。

## 消费端

- 新 Windows 客户端收到 `state_source=system_current_state` 后，不再用本地裸人数覆盖服务器主来源结果。
  列表及星图以“上次”和提示文字标记未知，避免只靠颜色表达；未知更新不重复响铃。
- 前端优先采用当前状态版本携带的新鲜度。QQ 对未知更新只推进游标，不伪造新的来敌。
  名单更新使用最新人数，不保留历史最大人数；只有人数变化不重复发送相同人员表格。
- 每次重新启用预警先取当前 Bootstrap，不重放停止期间磁盘游标；同一启用周期内断线仍续接游标。
  内容不变不重排浮层，避免启动闪动。

## 发布与验收

先发布兼容服务端、机器人和客户端，再单独切换组织规则及 ESI 路线。
组织配置在管理界面独立 `off/shadow/on`，档案必须 `on` 才执行；网络切换使用受保护的
`ESI transport rollout`，流程见[部署文档](server-deployment.md#受保护的-esi-转发切换)。
生产须验证真实截图到 114、SSE 到预警端、QQ 队列到实际投递的时延，不能用数据库单测耗时替代。
双节点错峰清空、快速开关、旧会话迟到、截断接管、服务重启及写入失败均有本地回归用例。
