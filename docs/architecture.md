# 系统架构

## 组件

| 组件 | 目录 | 职责 |
| --- | --- | --- |
| Windows 监控客户端 | `app/ui/`、`app/engine/` | 窗口选择、截图、红框检测、OCR、身份日志校验、心跳和 SSE 预警浮窗 |
| 情报服务 | `app/server/` | 数据存储、角色解析、敌我分类、实时态、告警、认证和 SSE |
| Web 管理系统 | `frontend/` | 态势图、来袭报表、账号和管理员功能 |
| QQ 机器人 | 独立部署 | 使用只读服务密钥读取 Bootstrap 和 SSE，发送主动预警 |

生产服务端使用 PostgreSQL，启动时只加载有界热数据；JSON 存储仅保留为兼容模式。

## OCR 与预警流程

```text
选中的 EVE 窗口
  -> 窗口截图和成员列表区域
  -> 红色敌对图标检测（即时预警触发依据）
  -> POST /api/v1/hostile-presence（立即上报数量）
  -> 数量或敌对姓名行变化时执行完整名单 ONNX OCR，失败有限重试（增效信息）
  -> POST /api/v1/ocr/snapshot（上传全部文字框和红色图标框）
  -> 服务端同行筛选、批量 ESI 解析与敌我分类
  -> active intel / alert
  -> PostgreSQL hostile wave（敌对出现至清空）
  -> SSE /api/v1/events
  -> 客户端浮窗、Web 页面、QQ 机器人
```

OCR 可在客户端设置中关闭，不影响红色图标检测和数量预警。客户端上报的是当前截图中的
名单快照，不自行查询角色军团、联盟或 standings。
服务端维护实时名单的新增、刷新和消失状态，并且只把确认存在的角色纳入统计。
线上 PostgreSQL 另以星系聚合 active intel：0→>0 新建波次，>0→0 关闭波次。波次使用
独立追加式生命周期表，因此不会因 active-intel 的实体 ID 复用而覆盖上一轮记录，也不需要
在服务启动时加载全量历史。`hostile_waves.peak_hostile_count` 保存波次期间的视觉敌对峰值；
同一客户端的 Presence 与 OCR 行按 `client_id` 去重，同星系多客户端取当前最大红色图标数。
因此 OCR 没有识别出人员时，视觉波次仍然成立并进入历史统计。

红色敌对图标是即时预警的触发条件，会先触发本地星系预警并独立上传数量。OCR 在敌对图标
数量发生非零变化或敌对姓名行画面变化时执行；完整 OCR 成功后立即结束当前重试，只有空结果
才有限补偿后续帧。客户端上传完整名单文字框和红色图标框，服务端按纵向同行筛选敌对姓名，
兼容状态图标与姓名被 OCR 合并成同一文字框。OCR 只补充角色、军团、联盟和威胁度等有效
信息，不会阻塞、延迟或替代红色图标预警。多窗口共用一个有界 OCR
调度器，首轮扫描错峰执行，每个窗口的离线上传队列只保留最新数量，避免任务随扫描轮次
累积。服务端批量查询 ESI，持久缓存已确认身份、短时缓存未找到结果，并合并并发缓存缺失；
zKill 角色链接直接由 `character_id` 生成。服务端收到数量后立即更新事件流；星系敌对全部
消失时发布安全状态。

敌我分类在服务端完成，不能把截图中的共享红色图标计数直接附加到每一名 OCR 角色。对每个
角色，服务端优先使用明确的敌对证据（黑名单名称、敌对军团/联盟或敌对 standing）；只有在
没有敌对证据且 ESI 或白名单已确认友好时，才返回 `white` 并抑制该角色的共享红色图标证据。
身份尚未由 ESI 解析确认的 detector 角色不会进入敌对人员明细。敌对历史接口和活动告警构建
会排除 `white` 分类及 `friendly_*` 证据；读取旧的 detector `red` 快照时会重新核验持久化
身份资料，避免历史记录复活已确认的友军。这样“视觉敌对人数”与“已确认敌对人员数”保持
两个独立指标，机器人和 Web 页面都必须按接口提供的敌对名单消费，不能使用 OCR 原始名单
或单条告警的 `names` 长度自行推断。

## 当前星系与多账号

客户端会定时刷新 EVE 窗口列表，但开始监控后只启动当前下拉框所选窗口的采集线程。
窗口标题中的角色名用于匹配对应的本地聊天日志，当前星系从该角色最新的 Local 日志
读取。新开的 EVE 窗口会进入下拉列表，切换窗口后需重新启动监控才能改变采集目标。

## 身份和权限流程

```text
EVE SSO、管理员密码登录，或管理员代签
  -> 创建桌面设备密钥
  -> 有效密钥立即获得客户端访问权限
  -> 密钥风控关闭：直接使用，不执行 ESI 身份任务
  -> 密钥风控开启且用户启用 Listener 扫描：读取最近修改的 EVE 日志
  -> 从文件名末尾取得 character_id 后 POST /api/v1/client/identity-checks
  -> PostgreSQL 幂等任务立即确认
  -> 服务端 worker 异步解析并退避重试
  -> 允许军团或用户角色白名单持续风控
```

客户端在开启功能前只校验密钥是否可用。Listener 后台任务默认关闭；用户显式开启后，
仅检查最近 24 小时修改过的 `Local` / `本地` 日志，按文件名末尾的 `character_id` 分组并
只读取每个角色最新的一份，最多处理 64 个角色。
后续仅在目录变化或每 30 秒兜底检查时发现新增文件；API Key 变化保留已处理文件记录，不回放历史。
认证或网络失败按 30 秒到 10 分钟指数退避。没有 Listener 不算
失败，发现新角色 ID 时才提交校验。客户端重复提交同一 ID 集合只读取既有任务状态，不会
重复调用 ESI 或记录成功日志；服务端直接按 ID 查询角色和军团资料，不执行名称搜索。确认
违规会禁用整个用户并吊销全部会话和密钥。

## Web 与部署边界

Python 服务只提供 JSON API 和 SSE，不托管旧内嵌网页。生产环境由 OpenResty/Nginx
托管 `frontend/dist`，并把 `/api/` 反向代理到 `127.0.0.1:8765`。SSE 路径必须关闭
代理缓冲。

PostgreSQL 连接由 `psycopg_pool` 复用，默认最小 2、最大 8 个连接。SSE 每 30 秒重新
检查一次认证状态，用户或密钥状态变化时会主动唤醒连接检查。

历史报告和观察记录通过 PostgreSQL 键集分页读取，普通列表默认最多 100 条。角色和星系
详情在 SQL 中按实体过滤；写入响应按 observation ID 点查对应告警。告警历史按时间倒序
惰性生成，达到请求上限后停止评分。预警 SSE 不读取完整 Bootstrap，也不扫描全部历史；
首次精简快照同时包含当前红色图标 Presence 和活跃情报引用的报告。

客户端从本地聊天日志确认星系变化时，会立即清除旧星系的本地预警，并强制下一帧把当前红色
图标数量重新上报到新星系；即使前后数量相同，也不会把旧星系的红色状态遗留在星图上。

## 数据来源

- OCR：当前 EVE 成员列表快照和红色敌对图标计数。
- EVE Chatlogs：客户端身份 `Listener`、所选角色当前星系；独立频道采集仍为兼容功能。
- ESI：角色、军团、联盟、standings、EVE SSO 和可选态势页授权。
- SDE：星系和星门拓扑。
- zKillboard：已解析角色的威胁度、击毁和损失等历史统计；在异步身份补全阶段按角色限速
  查询并缓存，只用于工作台和来袭分析研判。

zKillboard 不参与敌我分类和告警生成。外部服务失败时保留 ESI 分类结果，页面将缺失统计
显示为暂无数据，不构造战报数量或其他不存在的数据。
