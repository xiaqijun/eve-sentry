# 前端管理系统专项优化计划

## 目标

按照 Arco Design Pro 的管理系统标准，提升前端的稳定性、数据完整性、查询效率、实时状态可见性，以及明暗和窄屏适配能力。所有改动必须保持增量更新，不通过整页刷新恢复状态。

## 执行范围与优先级

### P0：稳定性与数据正确性

1. 在认证 API 的返回边界归一化数组和嵌套对象，避免服务端缺少字段时触发 `undefined.map`/`undefined.filter`。
2. 为路由增加统一错误边界，提供可恢复的错误页、重试和返回工作台操作。
3. 将来袭历史从固定 1000 条的前端分页改为服务端分页，并返回真实总数，避免历史数据静默截断。

### P1：管理台交互与性能

1. 统一查询页的加载、空数据、错误、刷新和提交中状态。
2. 修复用户创建失败仍关闭弹窗的问题，避免重复提交；将原生 `confirm/prompt` 替换为 Arco 对话框和表单。
3. 给用户、身份、白名单、审计和历史页面增加标准分页、筛选结果反馈和详情抽屉状态保持。
4. 统一轮询和 SSE 状态管理：隐藏页面停止非必要轮询，避免请求重叠，显示实时连接/重连状态。
5. 修正导航激活状态、服务状态文案和关键操作反馈。

### P2：体验、响应式与维护性

1. 为窄屏侧栏增加可理解的图标提示或抽屉式导航，确保表格不产生页面级横向滚动。
2. 补全登录页和管理页暗黑模式边界样式，统一主题切换按钮在窄屏下的尺寸。
3. 对路由进行懒加载，压缩登录背景资源，降低首屏 JavaScript/CSS 体积。
4. 清理未使用的旧工作台组件和重复 CSS，按功能拆分样式。

## 验收标准

- API 返回缺少数组字段时，页面仍能渲染空状态而不是崩溃。
- 任意页面运行时异常都显示可恢复错误页，不显示 React Router 默认异常页。
- 历史查询的总数和分页来自服务端，超过 1000 条仍可查询。
- 所有新增/删除/修改操作都有提交中、成功和失败反馈，失败时保留用户输入。
- 页面隐藏时非必要轮询停止；实时连接状态可见，恢复后不需要整页刷新。
- 390px、768px、1280px 下无页面级横向滚动；明亮/暗黑模式文字与边框清晰。
- `npm test`、`npm run build` 和 CI 前端检查全部通过。

## 实施记录（2026-08-10）

- 已完成 API 返回边界归一化：用户、密钥、白名单、军团、审计、客户端清单和 Bootstrap 的数组/嵌套对象缺失时均回退为空集合或安全默认值，避免 `undefined.map`、`undefined.filter` 导致页面崩溃。
- 已增加 React Router 全局可恢复错误页，支持重新加载和返回工作台，并保留错误编号用于排查。
- 已为 SSE 告警和 Bootstrap 事件增加 JSON 解析保护；后台标签页不再继续执行 React Query 定时刷新。
- 已修复用户创建请求失败时错误关闭弹窗的问题，失败会保留表单内容并显示错误。
- 已补充 API 边界异常响应测试；前端测试 20 个文件/100 个用例通过，生产构建通过。

### 后续迭代边界

历史接口当前仍兼容既有 `limit=1000` 协议。服务端分页需要同时改造告警重建、波次聚合和报表统计，下一阶段将以 `page/page_size/items/total/has_more` 形式落地，避免在聚合未完成前破坏现有报表语义。

## 样式与管理系统标准化实施记录（2026-08-10）

- 共享页面头部增加标题层级、可选副标题、操作工具栏语义和响应式排版。
- 统计摘要卡片统一高度、数字字形、间距、悬停反馈和暗黑主题边界。
- 管理表格、卡片、分页和筛选区统一边框、圆角、阴影、间距和窄屏断点；表格长内容在局部容器内处理，不撑破页面。
- 用户、身份、白名单和设备密钥列表补齐前端分页及加载状态，筛选条件变化时回到第一页。
- 保留星图工作台的专用视觉系统，管理台标准化不会覆盖星图 Canvas 的布局和颜色语义。

## 验证与交付

每个阶段补充对应的单元或组件测试，最后执行全量测试、生产构建和 GitNexus 变更影响检查。完成后更新 `docs/web-console.md`，使用 Conventional Commit 提交并通过代理推送 `main`。
