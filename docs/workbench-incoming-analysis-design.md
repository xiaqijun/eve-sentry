# 工作台与来袭分析重构设计

## 目标

工作台用于实时处置，来袭分析用于历史研判。两者共享同一套已验证敌对数据，
但不重复展示同一批趋势、排行和历史摘要。星图态势保持现有交互与布局。

本次同时接入 zKillboard 角色统计，为已通过 ESI 解析的角色提供外部战斗风险指标。
该指标用于排序和研判，不参与敌我身份判定，也不影响实时告警是否生成。

## 数据定义

### 身份分类

身份分类继续由本地配置和 ESI 联系人关系产生：

- `red`：黑名单、敌对军团、敌对联盟或敌对联系人声望命中。
- `white`：白名单、友军军团、友军联盟或友好联系人声望命中。
- 未分类：没有足够的敌我关系证据。

分类回答“是不是敌对”，不再把固定的兼容分数描述为人员威胁度。

### zKillboard 威胁度

角色通过 ESI 解析得到 `character_id` 后，服务端读取：

`GET https://zkillboard.com/api/stats/characterID/{character_id}/`

使用 zKillboard 返回的 `dangerRatio` 作为 `zkill_danger_ratio`，范围为 0 到 100。
同时保留以下研判字段：

- `gangRatio`：组队活动占比。
- `soloRatio`：单飞活动占比。
- `shipsDestroyed` / `shipsLost`：历史击毁与损失数量。
- `iskDestroyed` / `iskLost`：历史击毁与损失 ISK。
- `fetched_at`：服务端抓取时间。

这些是 zKillboard 的历史聚合统计，不代表角色当前所在舰船、当前战斗能力或本次来袭意图。
页面统一标注为“威胁度”，并注明数据来自 zKillboard，不与告警严重度混用。

### 获取与降级

- zKillboard 查询在客户端上报确认之后的异步身份补全阶段执行。
- 成功结果按角色缓存 12 小时；无数据和请求失败短期缓存，避免重复轰击外部服务。
- 请求设置明确的 User-Agent、短超时和最小请求间隔。
- zKillboard 不可用时保留敌我分类和实时告警，前端显示“暂无 zKill 数据”。
- 未取得 ESI `character_id` 的 OCR 名称不查询 zKillboard。

## 页面职责

### 工作台：实时处置

工作台只使用实时 bootstrap 数据，不再请求 7 天历史报表。

首屏信息：

1. 在线监控星系数。
2. 当前已验证敌对人数。
3. 当前敌对告警事件数。
4. 异常或离线监控客户端数。

主要区域：

- 当前敌对星系：按当前敌对人数、最高威胁度排序，展示人员、在线节点和最后变化。
- 最新告警事件：展示当前敌对告警，突出时间、星系、人员和告警级别，不引入人工确认状态。
- 监控覆盖：展示在线、异常、离线节点状态及其所在星系。

移除内容：7 天趋势、历史风险分布、数据有效率、历史排行、最近历史来袭。

### 来袭分析：历史研判

来袭分析使用两类数据：红色图标 Presence 形成的波次生命周期用于计算波次数量和视觉
峰值；指定时间范围内的已验证敌对告警用于事件、趋势、星系和人员研判。OCR 未识别出
人员不会使真实视觉波次消失。

核心指标：

- 有效来袭事件数。
- 来袭波次数。
- 独立敌对角色数。
- 涉及星系数。

分析区域：

- 来袭趋势：按时间范围使用 2 小时、天或月分桶。
- 来袭波次：同一星系敌对总数从 0 变为大于 0 时开始，全部清空时结束；清空后再次出现
  开启新波次，不按固定时间间隔拆分。多客户端同时监控同一星系时按服务端聚合状态判断，
  单个客户端清空不会提前结束波次。列表分别显示视觉峰值和已识别人员数，不能互相替代。
- 热点星系：事件数、目标人次、独立目标和最后出现时间。
- 人员研判：出现批次、跨星系范围、最后出现时间和威胁度。
- 最近告警记录：展示所选时间范围内最新 12 条有效敌对告警，作为明细核对入口；它不是
  来袭波次列表，也不承担实时处置。

告警严重度分布不再作为主要图表，因为当前敌对分类的兼容严重度固定为 `critical`，
展示该分布会制造不存在的层次。

## 数据契约

`verified_characters` 在现有字段基础上增加可选字段：

```json
{
  "character_id": 443630591,
  "name": "The Mittani",
  "zkill": {
    "danger_ratio": 68,
    "gang_ratio": 99,
    "solo_ratio": 0,
    "ships_destroyed": 1043,
    "ships_lost": 179,
    "isk_destroyed": 1888837094625,
    "isk_lost": 14433360680,
    "fetched_at": "2026-08-03T00:00:00Z"
  }
}
```

字段缺失表示尚未获取或 zKillboard 没有可用统计。前端不得使用告警 `score` 回填人员的
威胁度。

## 验收标准

- zKillboard 不可用时，上报、身份解析、告警和页面仍正常工作。
- 同一角色在缓存有效期内不会重复请求 zKillboard。
- 人员威胁度只显示 zKillboard `dangerRatio`，来源和更新时间可见。
- 工作台不再发起历史报表请求，页面只展示实时处置数据。
- 来袭分析可以按 24 小时、7 天、30 天和全部范围切换。
- 来袭波次由 PostgreSQL `hostile_waves` 生命周期确定，事件数和独立人员再用同时间段内
  的已验证敌对告警补充；热点星系和人员排行继续由已验证敌对告警确定性计算。
- 红色图标数量是波次成立的主证据，`peak_hostile_count` 保存一次波次内的视觉峰值；即使
  OCR 没有识别出人员，该波次也必须计入统计。OCR 和身份核验只补充已识别人员明细。
- 历史遗留且视觉峰值为 `0`、同时没有已验证敌对告警的空生命周期不参与波次统计。
- 暗黑与明亮主题、桌面与窄屏布局均不发生文字遮挡或横向溢出。
- 人员、星系和客户端等长文本必须完整换行显示，不允许通过省略号或裁剪隐藏内容。
