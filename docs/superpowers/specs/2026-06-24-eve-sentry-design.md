# EVE Sentry — Design Spec

> 2026-06-24 | EVE Online 敌对玩家预警桌面应用

## 概述

EVE Sentry 是一个 Windows 桌面应用，通过屏幕 OCR 识别 EVE Online 游戏内本地频道的**右侧成员列表**，将成员名字与用户维护的友方白名单比对，不在白名单内的名字视为威胁并触发预警。

## 技术选型

| 层面 | 选择 | 理由 |
|------|------|------|
| 语言 | Python 3.11+ | OCR 生态最强、开发快 |
| UI 框架 | PyQt6 | 成熟桌面框架，信号/槽天然支持多线程通信 |
| OCR 引擎 | PaddleOCR | 中英文混合识别强、pip 安装简单 |
| 窗口操作 | pywin32 (win32gui) | Windows 窗口枚举、坐标获取 |
| 截图 | Pillow (ImageGrab) | 轻量、与 PaddleOCR 输入格式兼容 |
| 打包 | PyInstaller | 单 exe 分发 |

## 架构

### 多线程分离（方案 B）

```
Main Thread (PyQt UI)              Worker Thread (QThread)
     │                                    │
     │── start(region) ───→               │
     │                                    ↓
     │                               sleep(interval)
     │                                    ↓
     │                              capturer.screenshot(x,y,w,h)
     │                                    ↓
     │                              ocr.recognize(image)
     │                                    ↓
     │                              提取名字列表
     │                                    ↓
     │                              detector.check(names, whitelist)
     │                                    ↓
     │                     ┌─ 无新威胁 → 继续循环
     │                     └─ 有威胁 → emit threat_detected──→ 弹窗+声音
     │                                    │
     │── stop() ──────────→              ✕
```

## 组件设计

### 1. capturer.py — 窗口识别 + 截图

**两种模式**：
- **窗口识别（默认）**：用 `win32gui` 枚举顶层窗口，按标题关键词匹配 EVE 客户端（默认 `"EVE -"`），获取窗口客户区坐标后截图
- **手动框选（兜底）**：用户鼠标拖拽选择右侧成员列表区域，保存坐标

**窗口查找逻辑**：
1. `EnumWindows` 遍历所有窗口
2. 按 `GetWindowText` 标题包含 `"EVE -"` 过滤
3. 找不到则按进程名 `"exefile.exe"` 匹配
4. 支持用户自定义关键词
5. 取 `GetClientRect` + `ClientToScreen` 获取客户区屏幕坐标

**截图**：
- `ImageGrab.grab(bbox=(x, y, x+w, y+h))` 返回 PIL Image

### 2. ocr.py — OCR 识别

- 封装 PaddleOCR，初始化时加载模型（只需一次）
- 输入 PIL Image，可选灰度化 + 对比度增强预处理
- 输出 `[(text, confidence), ...]` 按行排列
- 过滤 `confidence < 0.7` 的低置信度结果

### 3. detector.py — 威胁检测

- 输入：OCR 文本行列表 + 白名单集合
- 每行就是一个名字，直接与白名单比对
- 白名单支持：
  - 精确匹配
  - 简单通配符（`*` 和 `?`）
- 输出：不在白名单中的名字列表
- **去重 + 冷却**：同一名字在 60 秒内不重复报警

### 4. worker.py — 工作线程

- 继承 `QThread`，循环执行 capturer → ocr → detector
- 扫描间隔 2 秒/次（可调，1–10 秒），指两次截图之间的等待间隔（OCR 耗时不计入）
- 发现威胁发射 `threat_detected` 信号
- 发射 `status_update` 信号（扫描次数、当前状态）

### 5. whitelist.py — 白名单模型

- JSON 文件持久化，存放于可执行文件同级目录 `whitelist.json`
- CRUD：添加、删除、查询、获取全部
- 支持从文本文件批量导入（每行一个名字）
- 线程安全（用 `threading.Lock` 保护读写）

### 交互

- **开始监控**：按钮切换为"停止监控"，自动定位 EVE 窗口并启动工作线程
- **重选区域**：弹出半透明遮罩，用户鼠标拖拽框选成员列表区域
- **白名单**：支持手动添加/删除，从文件批量导入
- **告警弹窗**：模态弹窗显示威胁名字列表 + 播放 `alert.wav`
- **系统托盘**：关闭到托盘，托盘图标右键菜单有"显示/退出"

## 错误处理

| 场景 | 处理 |
|------|------|
| 找不到 EVE 窗口 | 提示用户检查游戏是否运行，切换到手动框选模式 |
| OCR 识别失败/超时 | 跳过当前帧，日志记录，不影响后续扫描 |
| 截图区域被遮挡 | 当前帧结果丢弃，下次重试 |
| 白名单文件损坏 | 提示用户，回退到空名单（全部报警，安全侧） |

## 测试策略

- `capturer` — mock win32gui 返回值测试窗口匹配
- `ocr` — 使用 EVE 本地频道截图样本做回归测试
- `detector` — 白名单匹配/通配符/去重逻辑单元测试
- `worker` — 信号发射用 Qt 测试框架验证
- 不做 UI 自动化测试（收益低）

## 排除

- 不接入 ESI API（后续版本考虑）
- 不做屏幕视频录制
- 不做远程推送通知（后续版本考虑）
- 不做多语言界面（仅中文）
